Quai 的 EVM 与传统 EVM 之间的主要区别如下所示。

<AccordionGroup>
  <Accordion title="地址分片">
    每条分区链根据地址前缀包含一组[独特的 Quai 与 Qi 地址](/cn/learn/advanced-introduction/hierarchical-structure/sharding)。前缀标明了该地址所属的分片与账本。
  </Accordion>
  <Accordion title="API 方法与命名空间">
    [go-quai 客户端 API](/cn/build/playground/overview) 与以太坊非常相似，但使用 `quai_` 命名空间而非 `eth_` 命名空间。该 API 包含许多（但并非全部）与以太坊相同的方法。
  </Accordion>
  <Accordion title="互操作性操作码">
    Quai 的 EVM 支持传统的 [Solidity](/cn/build/smart-contracts/solidity) 智能合约。
  </Accordion>
  <Accordion title="额外工具">
    以太坊工具与 [Quai 专用工具](#可用工具)均可用于在 Quai 网络上进行构建。
    更多详情请参阅[将您的以太坊应用迁移至 Quai](#将您的以太坊应用迁移至-quai)。
  </Accordion>
  <Accordion title="交易类型">
    与典型 EVM 相比，Quai 引入了额外的[新交易类型](/cn/build/transactions/types)，以处理跨链交易与 UTXO 交易。
  </Accordion>
</AccordionGroup>

## 将您的以太坊应用迁移至 Quai

以太坊应用通常由 Ethers、Web3.js、Viem 和 WAGMI 的某种组合构建而成。*只要*您使用 Pelagus 钱包作为注入式提供程序（injected provider），这些工具在 Web 端 dApp 开发中即可开箱即用。

如果您使用其他钱包或构建非 Web 端 dApp，仍然可以使用上述工具查询链上数据，但在发送交易时需要集成或迁移至 [Quais SDK](https://www.npmjs.com/package/quais)。

Quais SDK 是 [Ethers v6](https://docs.ethers.org/v6/) 的分支。因此，Quais 的语法与 Ethers 几乎完全一致，仅应用了上述多链与命名空间调整。如果您的应用目前基于 Viem 或 Web3.js 构建，以下指南可帮助您理解现有代码到 Quais 的语法映射：

- [**Viem 至 Ethers 迁移指南**](https://viem.sh/docs/ethers-migration)
- [**Web3.js 至 Ethers 迁移指南**](https://docs.ethers.org/v5/migration/web3/)

除了依赖提供程序轮询（provider polling）的方法之外，Ethers、Viem 和 Web3.js 中几乎所有现有函数与实用工具在 Quais.js 中都有直接对应的同名或相似方法。
