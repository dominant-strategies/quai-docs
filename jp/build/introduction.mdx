Quai の EVM と従来の EVM の主な違いは以下の通りです。

<AccordionGroup>
  <Accordion title="アドレスシャーディング">
    各ゾーンチェーンは、各アドレスのプレフィックスに基づいて[固有の Quai および Qi アドレスのセット](/jp/learn/advanced-introduction/hierarchical-structure/sharding)を含みます。プレフィックスは、そのアドレスがどのシャードおよび台帳に属するかを示します。
  </Accordion>
  <Accordion title="API メソッドと名前空間">
    [go-quai クライアント API](/jp/build/playground/overview) は Ethereum の API と非常に似ていますが、`eth_` 名前空間ではなく `quai_` 名前空間を使用します。また、同じメソッドの多くを備えていますが、すべてが同一というわけではありません。
  </Accordion>
  <Accordion title="相互運用性オペコード">
    Quai の EVM は従来の [Solidity](/jp/build/smart-contracts/solidity) スマートコントラクトを処理できます。
  </Accordion>
  <Accordion title="追加ツール">
    Quai ネットワーク上での開発には、Ethereum 向けツールと [Quai 専用ツール](#利用可能なツール)の両方を利用できます。
    詳細は [Ethereum アプリを Quai へ移行する](#ethereum-アプリを-quai-へ移行する) をご覧ください。
  </Accordion>
  <Accordion title="トランザクションタイプ">
    Quai では、クロスチェーンおよび UTXO トランザクションを処理するために、通常の EVM に加えて[新しいトランザクションタイプ](/jp/build/transactions/types)を採用しています。
  </Accordion>
</AccordionGroup>

## Ethereum アプリを Quai へ移行する

Ethereum アプリケーションは通常、Ethers、Web3.js、Viem、WAGMI などを組み合わせて構築されます。Pelagus ウォレットをインジェクトされたプロバイダーとして使用する*限り*、これらのツールはウェブベースの dApp 開発においてそのまま動作します。

別のウォレットを使用する場合やウェブベース以外の dApp を構築する場合でも、チェーンデータの照会にはこれらのツールを引き続き利用できますが、トランザクションの送信には [Quais SDK](https://www.npmjs.com/package/quais) を組み込むか移行する必要があります。

Quais SDK は [Ethers v6](https://docs.ethers.org/v6/) のフォークです。そのため、上述の差分が適用されている点を除けば、Quais の構文は Ethers とほぼ同一です。現在のアプリケーションが Viem または Web3.js で構築されている場合、既存コードを Quais の構文にマッピングする上で以下のガイドが役立ちます。

- [**Viem から Ethers への移行ガイド**](https://viem.sh/docs/ethers-migration)
- [**Web3.js から Ethers への移行ガイド**](https://docs.ethers.org/v5/migration/web3/)

プロバイダーのポーリングを利用するメソッドを除き、Ethers、Viem、Web3.js の既存の関数やユーティリティの大半は、Quais.js 内の同一または類似のメソッドに直接対応しています。
